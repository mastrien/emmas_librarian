### 3. Caminhos Infelizes (Unhappy Paths) Não Testados e Vulnerabilidades de Resiliência
1. **Parser de JSON das Respostas de IA (`AIService.ts`)**:
   - Em `electron/services/AIService.ts` (linhas 215, 304, 367), há chamadas diretas a `JSON.parse(result)`. Caso o provedor de IA retorne um JSON ligeiramente malformatado (ex: vírgulas sobressalentes, aspas não escapadas ou blocos markdown ```json ... ```), a aplicação lança uma exceção fatal sem reparo automático de JSON.
   - Na extração massiva (`massiveExtraction`), a falha de parse JSON em 1 de 10 perguntas aborta o lote inteiro e descarta o progresso de extração acumulado.
2. **Ausência de Timeouts HTTP nos Provedores de IA**:
   - Chamadas `fetch()` para OpenAI, Gemini e Ollama em `electron/services/AIService.ts` (linhas 43, 70, 99) não passam `AbortController` ou tempo limite. Se o endpoint do provedor congelar ou demorar para responder, a requisição trava indefinidamente.
   - Respostas de erro HTTP (500, 502, 503) não possuem política de repetição (retry with backoff) nem fallback automático.
3. **Tratamento de Exceções ao Extrair PDFs Corrompidos ou Sem Texto**:
   - Em `electron/services/PdfExtractor.ts` e `AIService.ts`, `pdfjsLib.getDocument()` não encapsula a leitura em blocos `try/catch` seguros durante a extração massiva. PDFs protegidos ou corrompidos disparam exceções brutas.
   - PDFs digitalizados (scanned PDFs) retornam zero texto (`totalCharacters === 0`), prosseguindo silenciosamente para a geração de embeddings e inserções no vetor de busca com strings vazias.
4. **Erros de Bloqueio de Banco (`SQLITE_BUSY`)**:
   - Operações em `DatabaseAdapter.ts` e repositórios não possuem retry automático para cenários de concorrência e bloqueio temporário do SQLite.
5. **Higiene de Testes e Avisos de React `act(...)`**:
   - Testes de componentes como `SearchPage.test.tsx` e `ArticleReaderPage.test.tsx` geram avisos no console de atualizações de estado fora do wrapper `act(...)`.
   - Vários testes utilizam mocks inline `any` em vez da classe fake nomeada `FakeProjectService.ts` (`src/services/__tests__/fakes/FakeProjectService.ts`), desrespeitando o padrão de projeto definido em `AGENTS.md`.

## Mudanças Propostas

Plano de ação claro, estruturado e acionável para sanar as vulnerabilidades de teste e resiliência.

### 1. Mocking do SQLite Nativo para Vitest (Isolamento de Ambiente)
- **Ação**: Criar um mock/fake em memória do adaptador SQLite (`electron/database/__tests__/fakes/FakeDatabaseAdapter.ts` ou mock do `better-sqlite3` via Vitest `vi.mock('better-sqlite3')`) para os testes unitários do Vitest.
- **Objetivo**: Garantir que `npm run test` execute em qualquer ambiente Node.js sem depender do binário compilado nativamente para Electron (`NODE_MODULE_VERSION`), eliminando a falha nos 10 arquivos / 77 testes do backend.

### 2. Expansão de Cobertura nos Módulos com Zero Cobertura
- **Prioridade 1 — Hooks e Utilitários de Domínio**:
  - Escrever suítes de teste para `useArticleFilters.ts`, `useProjectMetrics.ts`, `pdfTextSearch.ts` e `formatters.ts`.
  - Criar testes unitários para `GlobalErrorContext.tsx` e `ServicesContext.tsx`.
- **Prioridade 2 — Painéis e Modais de IA**:
  - Desenvolver testes de renderização e integração com fakes nomeados para `AIConfigPanel.test.tsx`, `AIChatPanel.test.tsx`, `AIQuestionnairePanel.test.tsx` e `ArticleDetailsModal.test.tsx`.
- **Prioridade 3 — Handlers IPC de IA**:
  - Criar `electron/ipc/__tests__/aiIpcHandlers.test.ts` com cobertura total dos handlers de IA.

### 3. Aprimoramento da Resiliência de IA e Leitura de PDFs
- **Parser com Reparo Automático de JSON (`jsonRepairParser`)**:
  - Implementar uma função utilitária `parseAndRepairJson` em `electron/services/llm/jsonRepair.ts` que:
    1. Remove delimitadores markdown (```json ... ```).
    2. Corrige vírgulas sobressalentes e aspas não escapadas.
    3. Permite recuperação parcial de chaves em extração massiva, evitando perda de dados do lote.
- **Timeouts HTTP e Retry com Exponential Backoff**:
  - Adicionar `AbortSignal.timeout(30000)` (30 segundos) em todas as chamadas `fetch()` dos provedores de IA (`OpenAI`, `Gemini`, `Ollama`, `Anthropic`).
  - Implementar política de retry (até 3 tentativas) para erros HTTP 429 / 5xx.
- **Tratamento de Exceções em PDFs**:
  - Envelopar a chamada a `pdfjsLib.getDocument()` em um bloco `try/catch` robusto em `PdfExtractor.ts`, retornando um objeto de resultado com flag `error` legível em vez de estourar a execução.
  - Notificar explicitamente quando o PDF for digitalizado/imagem sem camada de texto legível (`totalCharacters === 0`).

### 4. Qualidade de Testes e Limpeza de Avisos React `act(...)`
- **Envelopamento de Atualizações Assíncronas**:
  - Atualizar `SearchPage.test.tsx` e `ArticleReaderPage.test.tsx` utilizando `await act(async () => ...)` e `waitFor(...)` para eliminar todos os console warnings do React 18.
- **Padronização de Named Fakes**:
  - Refatorar testes de componentes para utilizar consistentemente `FakeProjectService.ts` e implementar fakes nomeados adicionais (`FakeAIService.ts`, `FakePdfExtractor.ts`), eliminando stubs inline com tipagem `any`.
